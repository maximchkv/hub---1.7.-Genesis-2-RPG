СОЗДАННЫЕ КОМПОНЕНТЫ UI KIT
================================================================================

### UIStyle.Spacing (расширен)
- `xs: 4` - для плотных интерфейсов
- `s: 8` - мелкие отступы
- `m: 12` - средние отступы (стандарт между секциями)
- `l: 16` - большие отступы
- `xl: 24` - очень большие отступы
- `xxl: 32` - максимальные отступы
- `section: 16` - между секциями
- `block: 12` - между блоками внутри секции
- `element: 8` - между элементами

### UIStyle.Layout.ContentWidthProvider
- Утилита для расчета ширины контента с капами
- Учитывает horizontalSizeClass
- Унифицированная логика: iPhone 360px, iPad 600-720px

### UIStyle.Layout.ScreenContainer
- Базовый контейнер экрана с правильной обработкой фона
- Использует паттерн `.background { }` вместо ZStack

### UIStyle.Layout.FixedHeaderScreen
- Паттерн для экрана с фиксированным заголовком поверх ScrollView
- Автоматический расчет contentWidth
- Передача contentWidth в header и content через closure

### UIStyle.Layout.StandardHeader
- Стандартный заголовок с кнопкой назад
- Два инициализатора: с/без trailing content
- Использует @ViewBuilder для trailing content

ИСКЛЮЧЕНИЯ И ОСОБЫЕ СЛУЧАИ
================================================================================

### StartView
- **Статус:** Не мигрирован
- **Причина:** Interactive background (LanternRevealLayer) требует `.ignoresSafeArea()` и ZStack
- **Решение:** Оставлен как есть, документировано как исключение
- **Приоритет:** Низкий (экран входа)

### TowerView
- **Статус:** Частично мигрирован
- **Что мигрировано:** Фон (ScreenContainer), ContentWidthProvider, стандартизированные отступы
- **Что сохранено:** Динамическая высота тактической секции через PreferenceKey
- **Документация:** `TOWERVIEW_LAYOUT_PATTERNS.md`

### BattleView
- **Статус:** Частично мигрирован
- **Что мигрировано:** Фон (ScreenContainer), ContentWidthProvider, стандартизированные отступы
- **Что сохранено:** Полноэкранный layout с bottom controls pinned to bottom edge
- **Примечание:** Bottom controls намеренно не используют safe area bottom (по UX требованию)
